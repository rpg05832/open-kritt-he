## התקנה בשלושה צעדים

1. **חלצו** את כל קובץ ה־ZIP לתיקייה קבועה בכונן המחשב (למשל `C:\SecurityScan`). לא מתוך ה־ZIP עצמו ולא בכונן רשת.
2. **לחצו פעמיים על Install.cmd.** ייפתח אשף בעברית עם חמישה שלבים: ברוכים הבאים, בדיקת המחשב, רשת ותעודות, התקנה וסיום.
3. **עקבו אחרי האשף.** הוא בודק מה חסר ומסביר בדיוק מה לעשות. בסוף הוא יוצר קיצורי דרך בשולחן העבודה ופותח את התוכנה.

אחרי ההתקנה פתחו בתוכנה את **"חשבונות"** וחברו חשבון AI שלכם. אין בחבילה חשבונות, מפתחות, סריקות או נתונים של המפרסם.

## מה מותקן במחשב

- **מנוע Docker אחד.** אם Docker Desktop כבר מותקן, התוכנה משתמשת בו. אם לא, האשף מציע שתי אפשרויות:
  - **מנוע מובנה (מומלץ):** סביבת Linux קטנה בתוך WSL של Windows, שמשמשת רק את התוכנה (כ־400 MB, בתיקייה `wsl-engine`). היא נבנית מ־Alpine Linux הרשמי (טביעת SHA-256 נבדקת) ומ־Docker Engine מהמאגר החתום של Alpine (Apache-2.0). בלי Docker Desktop ובלי תנאי מנוי. היא אינה פתוחה לרשת, משתמשת במגבלת הזיכרון הקיימת של WSL, ונעצרת יחד עם התוכנה. דרוש רכיב WSL של Windows; אם הוא כבוי, האשף מסביר איך להפעיל אותו.
  - **Docker Desktop:** האשף מוריד את המתקין מהאתר הרשמי של Docker, בודק את החתימה הדיגיטלית שלו (Docker Inc) ורק אז פותח אותו. את ההתקנה עצמה ואת התנאים של Docker אתם מאשרים בחלון של Docker.
- כל שאר הרכיבים (Node.js, Python, מסד נתונים, כלי הבדיקה) נבנים **בתוך Docker**, ולא מתפזרים ב־Windows. אין צורך ב־Git, Node או Python במחשב.
- נדרשים כ־15 GB פנויים, חיבור לאינטרנט ו־20–60 דקות בהתקנה הראשונה.
- התוכנה לא משנה את מגבלת הזיכרון של Docker, ומתאימה את עצמה לזיכרון הקיים.

## מה התוכנה בודקת

לפני שה־AI מתחיל, רצים במחשב שלכם כלים מקומיים. הם לא שולחים קוד החוצה:

- **כללים סטטיים** (Semgrep): 41 כללים עם הסברים בעברית ל־Python, JavaScript/TypeScript, React, PHP, Java, Go, C# ו־Ruby, למשל הזרקת SQL, הזרקת פקודות, XSS, פענוח לא בטוח וביטול בדיקת תעודות.
- **סודות** (Gitleaks): כ־150 סוגי מפתחות, סיסמאות ואסימונים, גם בגרסאות קודמות של הפרויקט. הסוד עצמו לעולם לא נשמר בדוח.
- **קובצי הגדרות** (Trivy): Dockerfile, Kubernetes, Terraform ותהליכי CI.
- **ספריות פגיעות** (OSV-Scanner): רק אם הפעלתם את בדיקת הספריות המקוונת. נשלחים למאגר OSV שמות וגרסאות של ספריות בלבד.

ה־AI מקבל את כל אלה כרמזים בלבד. הוא מאמת כל אחד מהם בקוד, מסנן התראות שווא, ובודק בעצמו גם תחומים שכלים לא מוצאים, כמו הרשאות, לוגיקה עסקית ומרוצי זמן.

### בדיקת תקינות קוד

ביצירת בדיקה אוטומטית בוחרים **מה לבדוק**: אבטחה, תקינות קוד, או גם וגם. בדיקת תקינות קוד מחפשת באגים, שגיאות שנבלעות, דליפות משאבים, בעיות ביצועים, קוד כפול, פונקציות מסובכות מדי וקוד חשוב בלי בדיקות. היא משתמשת בכלים מקומיים:

- **Ruff:** באגים נפוצים ב־Python.
- **Biome:** באגים ובעיות ב־JavaScript וב־TypeScript.
- **Lizard:** פונקציות מסובכות או ארוכות מדי, בכ־20 שפות.
- **jscpd:** קוד כפול בין קבצים. הקוד עצמו לא נשמר בדוח.
- **מיפוי קובצי בדיקות לפי שפה.**

הערות סגנון ועיצוב אינן נחשבות ממצא.

**מדד איכות:** בכל גרסה הכלים רצים על פרויקטי ניסיון עם 28 בעיות שתולות (21 חולשות אבטחה ו־7 באגים ובעיות תקינות), יחד עם קבצים תקינים מקבילים. נדרש זיהוי של 90% לפחות ואפס התראות שווא. בגרסה הנוכחית זוהו כל ה־28, בלי התראות שווא.

**עדכוני כלים:** הגרסאות נעולות בקובץ `app/engine/security-tools.json` עם טביעת SHA-256 רשמית. סקריפט העדכון בוחר רק גרסה יציבה שפורסמה לפני 14 יום לפחות.

## רשת מסוננת (נטפרי, אנטי־וירוס וכדומה)

סינון שבודק תעבורה מוצפנת מחליף את "תעודת האבטחה" של האתרים. Windows מכיר את התעודה של הסינון, אבל רכיבי התוכנה בתוך Docker לא מכירים אותה. בשלב **"רשת ותעודות"** האשף:

- בודק מתוך Docker את כל האתרים שמהם יורדים רכיבים, בדיוק כמו בהתקנה עצמה;
- מבחין בין **תעודה חסרה**, **כתובת חסומה בסינון**, **תקלת רשת** ו**רכיב תוכנה חסר**, ומסביר מה לעשות בכל מקרה;
- אם חסרה תעודה, מציג את פרטי הרשות (שם, תוקף, טביעות אצבע ואילו אתרים צריכים אותה) ומבקש את אישורכם. כפתור ברירת המחדל הוא "לא";
- מציע רק תעודה ש־Windows כבר סומך עליה ושבאמת משלימה את החיבור שנכשל. אפשר גם לבחור קובץ תעודה שקיבלתם מספק הסינון; קובץ עם מפתח פרטי נדחה.

התעודה שאושרה נשמרת בתיקיית `certificates` ונכנסת **רק לרכיבי התוכנה**. מאגר האמון של Windows לא משתנה, ובדיקת התעודות לא מבוטלת. כדי לבטל אישור, מחקו את הקובץ מהתיקייה ובנו מחדש מהאשף.

אם כתובת **חסומה** בסינון, תעודה לא תעזור. בקשו מספק הסינון לפתוח את הכתובת שהאשף מציין.

במסך **"מצב המערכת ותחזוקה"** שבתוכנה אפשר להגדיר מאגר GitHub של ההפצה. העדכון יורד מ־GitHub Releases, נבדק לפי טביעת SHA-256, ולפני ההתקנה נוצר גיבוי של מסד הנתונים ושל הקוד. אם העדכון נכשל, התוכנה חוזרת אוטומטית למצב הקודם.

## אימות החבילה

בתיקייה יש `SHA256SUMS.txt` ו־`SOURCE-MANIFEST.json` עם טביעת SHA-256 לכל קובץ. ליד קובץ ה־ZIP יש קובץ ‎.sha256 לבדיקת ההורדה כולה.

## רישיונות ותנאי ספקים

זו חבילת **קוד מקור והתקנה מקומית**. היא לא כוללת תמונות Docker מוכנות או קבצים בינאריים של ספקים.

- **Codex** (רישיון Apache-2.0) ו־**Claude Code** (תנאים קנייניים של Anthropic) מותקנים בזמן הבנייה במחשב שלכם, מהמאגר הרשמי של npm, בגרסאות קבועות. ההתקנה לא נותנת זכות להפיץ אותם מחדש, והשימוש בהם כפוף לתנאי הספק ולחשבון שלכם.
- **Cursor** ו־**Grok Build** הם תוספים קנייניים **אופציונליים, כבויים כברירת מחדל**. מי שרוצה אותם יכול להריץ את `install.ps1` עם ‎`-IncludeCursor` או ‎`-IncludeGrok`. ההורדה היא מהאתר הרשמי בגרסה קבועה, והבנייה נעצרת אם טביעת SHA-256 לא תואמת. קראו קודם את תנאי הספק.
- **המנוע המובנה** (Alpine Linux, Docker Engine, Docker Compose) מורד במחשב שלכם מהמקורות הרשמיים ואינו חלק מהחבילה. Docker Engine ו־Compose ברישיון Apache-2.0, ו־Alpine היא אוסף של רכיבי קוד פתוח ברישיונות שונים.
- **Docker Desktop** כפוף להסכם המנוי של Docker: חינמי לשימוש אישי, ללימוד ולעסקים קטנים (פחות מ־250 עובדים **וגם** פחות מ־10 מיליון דולר הכנסה שנתית). ארגון גדול יותר צריך מנוי בתשלום.
- מלאי הרישיונות שבתוכנה (תפריט "רישיונות וקרדיטים") הוא **מיפוי טכני ולא חוות דעת משפטית**. מי שמפיץ **תמונות Docker בנויות** או קבצים בינאריים חייב לטפל בעצמו בחובות של GPL/LGPL/MPL ושל רכיבי מערכת ההפעלה (כולל הנגשת קוד מקור), ואינו רשאי להפיץ את Claude Code או Cursor בלי הרשאה מהספק.
